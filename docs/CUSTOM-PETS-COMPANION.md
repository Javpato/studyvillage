# Custom animals and linked devices

## Using the features

Place and interact with the **Pet atelier** furniture indoors to create an animal. **Phone → Pets → Pet collection** manages and edits existing animals; creation and duplication are available only from the furniture atelier. Draw or import a static 64 × 64 PNG, or switch to the 448 × 256 animation sheet. Choose any existing ability independently of the template and house. Save to the collection or save and place its house. Collection entries are individuals: Duplicate makes a new ID; an individual can occupy only one house. Removing a house retains its custom animal. Empty houses still count toward the combined five-house limit.

Open **Phone → Settings folder → Devices** on both devices (also available in the app library and Settings → Controls). Give each a recognizable name. Create a code on one, then enter it on the other (or open the copied link). The creator approves the second device, chooses which device is the main player, and enables the tools. The code expires after five minutes and accepts only one companion. Changing roles or permissions requires disconnecting and pairing again.

The companion leaves its own world session; its saved profile is retained. Pairing does not exchange private identity keys or create another player in the main village. It uses a separate PeerJS connection and the existing signaling/STUN/TURN configuration, including when the main player is offline or using a server world.

The companion provides notebook, whiteboard, character atelier, animal atelier, focus clock, and voice/screen tools. It does not expose world movement, games or general decoration controls. Open the furniture atelier on the main player before using the companion animal editor; requests are rejected while that furniture interaction is closed. “Save and place” starts placement on the main device.

Opening a notebook or whiteboard opens the editor on the main device too. Closing one editor does not close the other. Notebook zoom, scrolling and whiteboard camera are local to each device. Whiteboard edits use the current main-device board and its actual editing permissions. Shared notebook edits go through the main player's existing shared-document authority, session and room checks. Conflicting private edits are reported rather than overwriting newer content.

The main device owns the focus timer. Changing or hiding companion views does not stop it. Configuration affects subsequent intervals.

Microphone capture may originate on the companion; normal world audience, mute and push-to-talk rules still apply. Voice needs an existing authorized village voice context. Audio output defaults to the main device/headphones. Choosing companion output suppresses playback on the main device and forwards other participants' audio; the user's microphone is never played back to them. Screen capture must be started on the device being captured. The browser's actual screen picker is used; unsupported capture is disabled with no substitute content. Main-device preview is sent to the companion.

Proximity movement now closes the old audience calls while retaining microphone capture and mute/PTT settings. Entering/leaving an explicit voice channel or leaving the world still revokes capture. Screen sharing retains its existing room/privacy boundaries.

## Persistence and resource conventions

- Local collection: `packages/runtime/src/storage/pets.ts`, IndexedDB `studyvillage-pets`. Like notebooks, the collection belongs to the local profile, not the temporary identity regenerated on reload. Active world ownership uses the current player identity. Backups include collection entries and validate artwork hashes.
- Definitions and behavior: `packages/core/src/pets/definitions.ts`, `model.ts`, `protocol.ts`. Stable pet IDs, chosen ability, house and artwork hash are separate fields.
- Artwork: `app/src/assets/pet-assets.ts`, `pet-custom.ts`, `pet-transfer.ts`; replaceable house/atelier/effect entries live in `app/public/sprites/manifest.json`. Original atelier/effect artwork is generated by `scripts/create-pet-atelier.py`.
- Custom sheet: 7 columns × 4 rows of 64 × 64 frames. Columns are idle, walk 1, walk 2, eat, pet reaction, rest, ability. Rows are down, left, right, up. Static imports expand to all frames. Gameplay uses semantic animation mappings in `CUSTOM_PET_ART`; jump lifts the custom drawing and ball/purr effects overlay it. Missing/invalid custom artwork falls back to the selected species and produces a development warning. Active local artwork is protected from cache eviction.
- Editor: `ui/pet-atelier.ts` reuses `ui/sprite-tools.ts` and the character atelier's styling. Collection/house assignment UI lives in `pets/collection-ui.ts`. Drawing operations are shared with `ui/vanity-ui.ts`.
- Pairing: `packages/core/src/companion/protocol.ts`, `packages/runtime/src/companion/session.ts`. Approved roles/tools, bounded assembly/backpressure, ordered commands, reply deduplication and timeouts. No village authentication secrets are sent.
- Companion views/ports: `app/src/companion/`, main hooks in `ui/app.ts`, notebook hooks in `notebooks/panel.ts`, field/object changes in `packages/documents/src/notebook-edits.ts`. Private notebook revisions and shared ink operation revisions prevent silent stale replacement.

## Recovery and limits

A lost connection restores ordinary controls and stops companion media. It does not silently activate another microphone. Reconnect using a new approved code. Pending editor commits remain in local storage; **Export pending work** in the connection panel exports recovery data. They are not automatically replayed into a different device, identity or room. This is draft recovery, not seamless session resumption.

The code/link flow is implemented; there is no QR scanner. Pairing depends on configured signaling and network reachability. iPad screen capture depends on browser support; installing StudyVillage on both devices cannot grant a capture API that the browser does not provide.
